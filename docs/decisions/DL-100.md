## DL-100 — The Python tests' CI budget is 120 seconds per shard

**Status:** Accepted · **Date:** 2026-10-26 · **Decided by:** Owner, on the agent's recommendation ·
**Serves:** NFR-01, NFR-09 · **Supersedes:** [DL-94](DL-94.md) item 10's 90-second figure for the
Python tests (its pipeline and CI-workflow budgets stand)

Superseded by [DL-101](DL-101.md) (item 1, the figure) and [DL-103](DL-103.md) (item 2, the shards).

### Context

DL-94 item 10 (Q9) held the Python test step to 90 seconds, checked in CI by
`schedule.python_tests_budget_seconds`, so a slow change is seen when it lands. ORC-09 met it by
running the suite as two shards. Before R1.4.3 the heavier shard already took 83 s of 90 (CI run
40267365831); R1.4.3's tests took it to 90 s (run 40295720437), every test passing. Its four workers
are evenly loaded, so the wall clock follows the shard's total work, and R1.4.3 added about 5 s of
it. A third shard made each shard slower (run 40299499933: 43, 94 and 104 s), because every shard
builds the shared session fixtures again.

### Decision

1. **The Python test budget is 120 seconds per shard**, a quarter above the suite as R1.4.3 left it.
2. **The suite stays two shards**, split by module as ORC-09 built it.
3. The pipeline's 5-minute and the CI workflow's 3-minute budgets are unchanged.

### Consequences

- A change that slows the suite by more than about a quarter still fails CI where it lands.
- The heaviest pre-existing module, `test_experiments.py`, is the lever if the suite nears this
  budget again; making it faster is a release of its own, not a reason to raise the figure again.
- CI runner minutes are free on a public repository (NFR-01); the budget is about feedback time.
