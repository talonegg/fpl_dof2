## DL-101 — The Python tests' CI budget is 150 seconds per shard

**Status:** Accepted · **Date:** 2026-10-26 · **Decided by:** Owner, on request ·
**Serves:** NFR-01, NFR-09 · **Supersedes:** [DL-100](DL-100.md) item 1 (its 120-second figure;
items 2 and 3 stand)

### Context

DL-100 set the Python test step's budget at 120 seconds per shard. Promoting R1.4.3, identical code
then took 64 s for the second shard on one CI run (40304041480, `dev/R1.4.3`) and 122 s on another
minutes later (40304074466, the promotion pull request), every test passing both times; the same
shard had earlier taken 73, 82, 110 and 126 s. The heaviest end-to-end tests had been trimmed and
the shard's workers finish together, so what remains is the runners' speed, which varies about
twofold.

### Decision

1. **The Python test budget is 150 seconds per shard.**

### Consequences

- A runner at the slow end of GitHub's range passes; a change that roughly doubles a shard's time
  still fails where it lands.
- A wall-clock budget on shared runners can still fail on an unusually slow runner. If it does
  again, the next step is a check that a breach repeats before it fails, not a higher figure.
