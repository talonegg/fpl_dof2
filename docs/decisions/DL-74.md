## DL-74 — Documentation restructured: one file per decision, closed plans archived, one home per fact

**Status:** Accepted · **Date:** 2026-10-17 · **Decided by:** the owner asked for the restructure, with
`heroesim` as the reference; an agent chose the shape below

### Context

The planning set was written for a build that has since finished. Agents paid for it on every task:
the decision log was one 315 KB file that code linked into by anchor, half the anchors already
broken; thirteen of fifteen epics, the model-improvement plan and the AI tooling plan were closed
but sat beside the live documents and in every search; the live debt register was §6 of the closed
E0, and the environment variables were §8 of a closed inputs list. `heroesim` solved the same growth
with a small decision log plus an index, archives that searches skip, and a rule of one home per
fact.

### Decision

1. **One file per decision.** Entries DL-01 to DL-73 moved, text unchanged, to
   `docs/decisions/DL-nn.md`; new entries are new files. `docs/decisions/README.md` holds the rules,
   the open decisions and an index generated by `python scripts/docs.py index`. This departs from
   `heroesim`'s per-release archive files: an agent reads only the entry it was sent to, and an entry
   never moves again, so its links never need re-pointing.
2. **Closed plans archived, text unchanged.** Epics E0–E7 and E9–E14, the original epic register and
   INPUTS-REQUIRED moved to `docs/planning/archive/R1.0/`; the model-improvement plan and the AI
   tooling plan to `docs/planning/archive/`. Its README indexes them. The project plan's superseded §3, §4, §7 and §8
   moved to `archive/02-superseded-sections.md`, leaving pointers so its numbering holds.
3. **Live sections lifted out first.** E0 §6 became `docs/planning/debt-register.md`; INPUTS §8
   became `docs/environment.md`, rewritten as current.
4. **A map and rules.** `docs/README.md` replaces `docs/planning/README.md` as the map of where each
   fact lives; `docs/agents/documentation.md` holds the writing and archiving rules. CLAUDE.md
   points to both.
5. **Search sees what is live.** `docs/.rgignore` leaves the archives out of a plain search.
6. **Checked in CI.** `python scripts/docs.py check` fails on a stale index, a relative link to a
   missing file, or a cited `DL-nn` with no entry. Every link into a moved file, in documents and
   code comments, was re-pointed; six links that were already broken were fixed.
7. **Releases are numbered `Rx.y.z`** (the owner's word). Every epic built so far, E0–E14, is
   **R1.0**; E8 stays live as in-season operations. The next release is **R1.1.0**, the data
   pipeline uplift, planned in `docs/architecture/R1.1.0-data-pipeline-backlog.md`. A release's plan
   is `Rx.y.z-<slug>.md` in `docs/planning/epics/`, archived to `archive/Rx.y.z/` when it closes.
8. **The principles file is not touched** (DL-16). Its links into moved files resolve through three
   stubs at the old paths — `docs/planning/00-decision-log.md` (keeping the headings it links to),
   `epics/E0-steel-thread-gw1.md` and `epics/E4-decision-engine.md` — until the owner re-points them.

### Consequences

- The documents an agent reads to orient (CLAUDE.md, the map, the epic register, the decision index)
  total roughly 40 KB, against a 315 KB log alone before.
- An accepted entry is still never edited; moving it with its text unchanged, re-pointing a link, and
  a `Superseded by` note are the only changes it takes.
- E14's Status line was filled when it was archived; DL-72's own Status still reads Proposed, which
  only the owner can settle.
