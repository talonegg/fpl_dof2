## DL-79 — R1.1.0 keeps its order after GW4; four design fixes join it; PIPE-09 narrowed; OD-04 closed

**Status:** Accepted · **Date:** 2026-10-17 · **Decided by:** Owner · **Serves:** OBJ-1, OBJ-7,
NFR-06, NFR-10, NFR-12

### Context

At the GW4 decision point the owner judged that **intuition is ahead of the model**. E8's rule for
that outcome is that the forecast takes priority. The open release, R1.1.0, is a data-pipeline
uplift. The 2026-10-17 design review ([architecture §12](../planning/03-solution-architecture.md#12-module-design--review-of-2026-10-17))
found four fixes that R1.1.0 items depend on (§13.2). PIPE-09 assumed the scrapers are attempted
daily; they are already off by default, and only The Odds API is on.

### Decision

1. **R1.1.0 keeps its order.** The pipeline is the prerequisite for a better forecast: point-in-time
   features (PIPE-01), multi-season history keyed on the permanent player code (PIPE-02) and unified
   odds (PIPE-05) are what a stronger model is built from. The GW4 outcome is answered by doing
   R1.1.0, not by setting it aside.
2. **Four design fixes join R1.1.0:**
   - **PIPE-12** — one clock and one "current gameweek" per run (03 §12 P4); before PIPE-01 and
     PIPE-10.
   - **PIPE-13** — one forecast-fitting interface in `forecast/` (P1); before PIPE-02 and PIPE-05.
   - **PIPE-04 widened** — the football-data.co.uk adapter also retires the fetch outside `sources/`,
     and the isolation test scans `scripts/` and names the source (P5).
   - **PIPE-06 widened** — branch restore done once, in one place (O3).
3. **PIPE-09 narrowed** to turning The Odds API off by default. The Understat and FBref adapters stay,
   dormant and off, in case access returns.
4. **OD-04 closed:** the FPL API's availability fields (status, chance of playing, news) are the
   injury source this season; no further feed is added.

### Consequences

- The backlog, the release register's to-dos, architecture §13.2 and the plan's issues I-07 and
  I-08 are updated to match.
- E8 records the GW4 outcome and points here for the response to it.
