## DL-81 — R1.1.0 is reopened: remediation before promotion

**Status:** Accepted · **Date:** 2026-10-19 · **Decided by:** Owner, on a code review of the build
· **Serves:** NFR-06, NFR-09, NFR-12

### Context

The R1.1.0 build (PIPE-01 … PIPE-14) landed on `dev/R1.1.0` on 18–19 October as fourteen direct
commits, without `feature/*` branches or pull requests (DL-80 §3), and the backlog was marked
Complete with every acceptance box ticked. A review of `1e1180c..2de1003` found:

- **The build is red.** `ruff format --check` fails, so CI on `dev/R1.1.0` fails before `mypy` runs;
  `mypy` reports errors in eight files. pytest and the web build pass.
- **A crash the suite cannot see.** `forecast/fit.py` calls `fixture_index_from_history` with its
  arguments out of order, so the historical chip replay (D-18, DL-28) raises on every deadline; only
  the `--slow` test reaches it.
- **Silent wrongness.** Gold relabels archive club codes through the 2026/27 id map; the live
  forecast can rate clubs with last season's team strength before GW1; `--as-of` freezes the clock
  but not the bronze it reads (look-ahead, Invariant 5); price history is stamped with the run time,
  so re-runs duplicate it and the replay cannot reproduce it; training now includes a half-played
  gameweek.
- **Invariant 1 in substance.** `gold/match_odds.py` parses football-data.co.uk's CSV format; the
  isolation test was satisfied by re-exporting from the `sources` root, and gained an FPL-API
  allow-list for three scripts with no waiver.
- **Operations.** Three workflows force-push `data` with no shared lock; the permanent archive would
  rewrite its gameweek tarball daily and fail every day out of season; the prospective odds feed
  reads bronze that nothing writes.
- **Unmet criteria ticked.** Four items meet none of their criteria in full (PIPE-01, 02, 04, 05),
  seven partly; PIPE-07, 08 and 09 are met.

### Decision

1. **R1.1.0 is reopened.** The backlog's Status reads "in remediation"; each box is ticked only where
   the code meets it, and an unticked box names the remediation item that closes it.
2. **The remediation plan is backlog §4** (REM-01 … REM-11), in the order given there: a green build
   first, then the permanent archive, because bronze evidence is lost every day it waits.
3. **Promotion is gated** on backlog §4.2: CI green including `mypy`; the slow chip replay run once
   and passing; every box ticked with the test that proves it; the pre-release smoke.
4. **Every remediation item is its own `feature/*` branch and pull request** into `dev/R1.1.0`
   (DL-80), and none merges with a red check.
5. **Behaviour changed without a record is restored, not ratified.** The training cutoff returns to
   the last *finished* gameweek, so no fit sees a gameweek in progress, and the cold-start
   team-strength guard returns (DP-08).
6. **Retrospective ingress is built in R1.1.0** (closes OD-07): a source added mid-season maps
   timestamped match logs to gameweek deadlines and backdates running totals best-effort, recording
   its method in the crosswalk. No live source needs it yet, so it is proven on recorded fixtures.
7. **The permanent archive ships with R1.1.0**, not ahead of it as a hotfix.
8. **The three scripts that call the FPL API directly read through the `fpl` adapter and bronze**;
   the isolation test's allow-list is removed rather than waived.
9. **Gold is fixed and built in R1.1.0; its first consumer comes in R1.2.** PIPE-02 and PIPE-05 are
   met when gold is built correctly by `transform`, not when a model reads it.

### Consequences

- R1.1.0 does not reach `main` this week. The permanent archive cannot run until it does, and bronze
  that leaves the 30-day window before then is lost; the owner accepts that loss (item 7).
- REM-09 grows by the retrospective ingress, and REM-06 by moving three scripts onto the adapter.
