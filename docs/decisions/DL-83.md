## DL-83 — Advanced metrics carry their capture time; backdating never estimates

**Status:** Accepted · **Date:** 2026-10-20 · **Decided by:** Agent, building REM-09 under
[DL-81](DL-81.md) item 6, recorded before · **Serves:** NFR-06, FR-37

### Context

The look-ahead gate (PIPE-10) checked timestamp columns that no strict silver schema has, so on real
tables only its price-history half could fire. `player_advanced` and `player_metric` carry the
gameweek a row was knowable for (`as_of_gameweek`) but not when it was captured, so there was
nothing to check that against. DL-81 item 6 asks for a source added mid-season to be backdated
"best-effort" from running totals. Interpolating a later total back over earlier gameweeks would
put data from after a deadline into that deadline's row, which is look-ahead (Invariant 5).

### Decision

1. **`player_advanced` and `player_metric` gain `observed_at`**, the moment a row's content became
   knowable: the bronze snapshot's fetch time for a live capture, or the latest event a backdated
   row includes. A merged `player_metric` row takes the latest of its contributors.
2. **The gate checks what the schemas hold.** In the current season, a metric row with
   `as_of_gameweek = N` must be observed no later than the GW *N* deadline. A `player_gameweek` row
   for GW *N* must kick off after that deadline; otherwise its outcome was already a feature when it
   was being predicted.
3. **A row's `as_of_gameweek` is the first gameweek whose deadline is still ahead**
   (`gameweek_ahead`), and is null after the season's last deadline, not clamped to it.
4. **Backdating maps timestamps forward; it never estimates.**
   - A timestamped match log counts each event towards every gameweek whose deadline is after it.
   - Running totals are stamped with the latest snapshot captured before each deadline.
   - A gameweek before the first snapshot gets no row. "Best effort" means a stale total carried
     forward, never one scaled back from a later total.
5. **The crosswalk records how a source's rows arrived:** `ingress` is `live`, `match_log` or
   `running_total`. Each row's `observed_at` is its provenance.

### Consequences

- Silver written before this change lacks `observed_at` and fails the strict schema. It is rebuilt
  by the documented command (REM-10), not migrated in place.
- Before its first snapshot, a running-totals source contributes nothing for the gameweeks it
  missed. That is information loss, accepted over look-ahead.
