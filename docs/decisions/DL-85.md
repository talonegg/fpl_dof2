## DL-85 — R1.1.0 is promoted with its one main-only box open; R1.1.1 verifies it

**Status:** Accepted · **Date:** 2026-10-21 · **Decided by:** Owner, on request · **Serves:** NFR-06,
NFR-09

### Context

The R1.1.0 promotion gate (backlog §4.2, [DL-81](DL-81.md)) asks that every §2 box be ticked or
descoped by a DL entry. One box cannot be ticked before promotion: PIPE-14's `snapshots` branch is
first written by a slow ingest running on `main`. Holding the release for it would hold the
permanent archive too, and bronze leaves the rolling window every day it waits.

### Decision

1. **R1.1.0 is promoted and tagged with that box unticked.** It stays unticked in the R1.1.0
   backlog, not ticked on trust.
2. **`dev/R1.1.1` verifies it after the tag.** Once the first slow ingest on `main` writes
   `snapshots`, the box is ticked there, naming the run that wrote it.
3. The same applies to any later box that only a run on `main` can show.

### Consequences

- Until R1.1.1 ticks it, the archive is built and tested but unproven in production. A failing
  first archive alerts through `alert-on-failure.yml`, as every slow ingest failure does.
