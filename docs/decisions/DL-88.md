## DL-88 — A hotfix takes R1.2.1; the second modular-platform drop becomes R1.2.2

**Status:** Accepted · **Date:** 2026-10-23 · **Decided by:** Owner, on request · **Serves:** NFR-06

### Context

R1.2.0 was tagged on 2026-10-23. Its first production run showed the prospective job's scoring
step failing on every score-only run: a restored ledger record leaves out `raw/`, and the frozen
`score.py` writes into it without creating it. The fault predates R1.2.0. The owner asked for it to
be fixed now as a hotfix rather than wait for MOD-06 to retire the harness. The release procedure
tags a hotfix with the patch number after `main`'s latest tag, R1.2.1 — the number
[DL-87](DL-87.md) gave the second drop of the modular platform.

### Decision

1. **The hotfix is R1.2.1**, by the release procedure: the CI glue (`pipeline/scripts/prospective_ci.py`)
   creates `raw/` before the frozen scripts run. The frozen bundle is unchanged.
2. **The second drop is renumbered R1.2.2.** Wherever DL-87 says R1.2.1 it now means R1.2.2; its
   content, order and acceptance are unchanged.

### Consequences

- The register, backlog and target architecture name the second drop R1.2.2.
- A later hotfix while R1.2.2 is open would take R1.2.2 the same way; the drop would move on again.
