## DL-90 — F1 ships: M7 reads each player's own card rate

**Status:** Accepted · **Date:** 2026-10-23 · **Decided by:** Owner, by the bug-fix rule in [DL-89](DL-89.md) item 2, applied in the R1.2.2 build · **Serves:** FR-04, FR-37, NFR-06

### Context

M7 (cards) reads each rate's `<column>_per90_last6` feature, but `yellow_cards` was not in
`forecast.features.rolling_statistics`, so the observed rate was always null and every player of a
position got the position prior (03 §12.6 F1). [DL-89](DL-89.md) item 2 made this a bug fix under
[E8 §5](../planning/epics/E8-ongoing-in-season-monitoring.md#5-the-bar-for-changing-the-model-mid-season)'s
exception, to ship once the backtest had graded it, and to stop and go to the owner if the
held-out season degraded.

The first graded run showed the variant identical to the champion to the last digit: the harness
built every entrant's feature rows from its own config, so a registry override on
`forecast.features` reached the fit but not the rows. The harness now builds rows per entrant
feature config (`Entrant.features`).

### Decision

1. **`yellow_cards` joins the default `rolling_statistics`.** The experiment `f1_card_rates`
   (variant `c3_f1`) is closed as shipped, and `c3_f1` is retired: it now equals `c3`.
2. **The bar applied** is the bug-fix reading of E8 §5 condition 1: the held-out season does not
   degrade. Degrading means any paired metric (MAE, Spearman, top-N precision) with a 95% bootstrap
   interval that excludes zero on the worse side. None did (below).
3. **A test pins the class of bug:** every `RATE_COMPONENTS` column (through `rate_sources`) has a
   rolling feature (`tests/test_experiments.py::test_every_rate_component_has_a_rolling_feature`).
   The other five components already had one.

### Consequences

- Measured locally, walk-forward over 2024/25 and 2025/26 (68 folds, 20,573 scored rows), `c3_f1`
  minus `c3` per gameweek with a seeded 95% bootstrap interval: MAE +0.00052
  [-0.00021, +0.00121], Spearman +0.00002 [-0.00089, +0.00094], top-N precision +0.00147
  [-0.00368, +0.00735]. Pooled MAE 1.9061 against 1.9056, RMSE 3.0566 against 3.0580. A small card
  term moves points by a few thousandths; the change is a correction in fact, not an improvement
  in score, and it is justified by that.
- The golden-artefact output changes only if its fixture has a card record to read; the suite
  states whether it was re-baselined.
- The CI backtest, not the local run, puts the result on the `ledger` branch; until it has run
  with this digest the record there does not exist.
