## DL-93 — Hotfix R1.2.4: training rows refresh when a gameweek is checked; dependencies are pinned

**Status:** Accepted · **Date:** 2026-10-23 · **Decided by:** Owner, on request ·
**Serves:** FR-08, NFR-06, NFR-07

### Context

Every player's current-season gameweek rows, which every strategy trains on, come from FPL's
per-player `element_summary`. That resource was cached for a week, on the reasoning that its
prior-season totals never change. The current season's rows in the same response change every
gameweek. On 2026-10-23 production's summaries dated from the 2026-10-16 sweep, before GW7 was
played, so the GW8 advice was trained without GW7. The same lag caused the purchase-price defect
fixed by [DL-92](DL-92.md). No gate noticed (03 §12.6 F2).

Separately, every workflow installed the pipeline's dependencies at their newest releases. pandas
3.1.0 broke the transform in CI while the local 3.0.5 passed, and a release could change model
output mid-season with no change to the code (DP-11).

### Decision

1. **The hotfix is R1.2.4.**
2. **A summary fetched before the latest gameweek was finished and checked is stale**, whatever
   its age. The moment comes from the oldest bronze `bootstrap_static` that shows it checked, and
   only the slow-path sweep applies it. The weekly TTL still holds otherwise.
3. **A warning gate, `player_gameweek_current`,** fires when more than
   `quality.maximum_lagging_player_share` of the players whose club played the latest finished
   gameweek have no row for it. It warns rather than blocks: stale rows still give advice, only
   older advice.
4. **Dependencies are pinned** in `pipeline/requirements.lock`, which every workflow installs with
   `-c`; a test fails a workflow that does not. An upgrade is a deliberate change that regenerates
   the lock and goes through CI. No Dependabot: its pull requests would target `main`, which takes
   pull requests from `pre-release` only.
5. **A waiver until ORC-05:** the season log's hindsight optimum is solved on placeholder clubs and
   £5.0m prices (`DP-WAIVER(DP-05)` in `publish/season_log.py`, debt D-31). It feeds no advice,
   and R1.3.0's ORC-05 replaces it with an optimum on real prices, clubs and bank.

### Consequences

- The first slow ingest after each checked gameweek re-fetches all summaries (about 670 requests),
  roughly one sweep per gameweek, as the weekly TTL gave.
- The structural fix, reading every source's freshness from its fetch time, stays with ORC-02.
- The debt register records what else this review deferred (D-30 to D-34).
