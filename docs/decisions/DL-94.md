## DL-94 — Build R1.3.0 as planned, with the owner's answers; a malformed capture never reaches history

**Status:** Accepted · **Date:** 2026-10-23 · **Decided by:** Owner, on request ·
**Serves:** FR-08, FR-09, NFR-01, NFR-06, NFR-07

### Context

The [R1.3.0 plan](../planning/epics/R1.3.0-gameweek-orchestration.md) refines the modular platform
backlog's gameweek orchestration ([DL-86](DL-86.md)) against what R1.2.x built, and asked the owner
nine questions. A capture that is whole but fails its source's contract stays the latest in bronze
today: `bronze verify` (PIPE-11) catches only torn and corrupt files, so such a capture fails the
run, and nothing stops it being read again as history.

### Decision

1. **R1.3.0 is built as the plan sets out**, in two drops: Drop A (advice that keeps up), then
   Drop B (every gameweek judged once), which takes the next free patch number when it is cut.
2. **A strategy's advice of record is its last success before the deadline**, stamped with its
   `as_of`, and a later failure is noted beside it. A strategy with no success records "no advice".
3. **A malformed capture never reaches history.** A capture that fails its source's contract is
   quarantined with its reason and never used again. Every reader then takes the last valid capture
   at or before its `as_of`: the live run, model training, the backtest and every replay. A capture
   is all or nothing: one malformed row makes it malformed. The staleness gates still judge the
   capture used, so the last valid one is never silently too old (Invariant 7). This is ORC-10.
4. **Any price, status or news change, any fixture move, and the first odds for the open gameweek
   each start a pipeline run**, with no thresholds; runs queue newest-wins and the freeze applies.
5. **The fast ingest's cadence is unchanged**: no fallback firings and no faster cron.
6. **The one scorer covers all four chips now.**
7. **The models history is rebuilt from the registered strategies** and published; the frozen-era
   tables are archived as records.
8. **WEB-02, the contract's minor version and the app's runtime check, moves into Drop A** from
   R1.4.0.
9. **D-33 waits for ORC-01**: the owner's first Free Hit is not expected before it.
10. **Run-time budgets**: a pipeline run within 5 minutes, the CI workflow within 3 and the Python
    tests within 90 seconds, checked in CI; `pytest-xdist` joins the pinned dev dependencies.

### Consequences

- Late odds reach the advice only when a fast ingest actually runs; ORC-02's dispatch makes them
  reach it at once when one does, and ORC-07's banner names the next check.
- The 2025/26 numbers on the Models page will move when ORC-06 publishes the rebuilt history.
- R1.4.0 starts with WEB-03 and WEB-01; its own questions are still open.
