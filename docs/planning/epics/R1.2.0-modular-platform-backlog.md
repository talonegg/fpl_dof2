## 1. Overview

Three modules downstream of the data pipeline — orchestrator, model factory, web — each changeable
on its own, meeting only at versioned contracts, so that new sources, new models, policy
experiments and UI experiments can land without touching the other modules
([05 §1](../05-target-architecture.md#1-goal-and-drivers)). Every release is a vertical slice that
leaves the weekly advice working; nothing here lands without the degradation checks its story
names.

## 2. R1.2.0 and R1.2.2 — Registry and five models live

### MOD-01: Module boundaries enforced; core extracted

- **Absorbs**: 03 §12 P3, P10.

#### Problem
Domain logic lives in the stage edge (XI selection, C1 orchestration, model choice, publish fitting
M2 and running the hindsight oracle); stages import each other's file-name constants; `week` and
`decision` load squad state with duplicated code; core modules do their own I/O
([05 §2.1](../05-target-architecture.md#21-orchestration)).

#### Design
1. `import-linter` contracts in CI: data platform → core → factory and orchestrator; the
   orchestrator reaches the factory only through the registry interface; nothing imports `stages`.
   It starts with an allow-list of today's violations; each story that touches the code shrinks it
   (a ratchet, DL-87).
2. `core` holds `rules/`, `squad/`, `optimise/` and `decision/`, pure: no file I/O, no config loading.
3. Domain logic moves out of `stages/` into the module that owns it; one artefacts module owns gold
   paths and file names (`DataLayout.gold_for(season)`); one `load_decision_context(ctx)`.

#### Acceptance criteria
- [x] `import-linter` runs in CI and fails on a new forbidden import, shown by a deliberate violation in a test fixture (R1.2.0). Done: contracts and allow-list in `pipeline/pyproject.toml`; `pipeline/tests/test_import_boundaries.py` injects a violation.
- [x] The allow-list is empty before R1.2.2 promotes. Done: every `ignore_imports` in `pipeline/pyproject.toml` is `[]`; MOD-06 removed `sources.fdcouk.adapter -> prospective.bundle` and MOD-08 the two `stages.backtest -> forecast.*` (the stage reaches the harness through `fpl_dof.factory`).
- [x] No module in `stages/` imports another stage; gold paths are built in one place. Done: `fpl_dof/artefacts.py` and `DataLayout.gold_for`; the independence contract has no ignores; `test_stages_and_publish_build_no_gold_path_by_hand`.
- [x] `core` performs no file I/O and reads no `os.environ` (P10). Done: `test_core_does_no_file_io_and_reads_no_environment` (AST scan; core was already clean).
- [x] `fpl-dof run` publishes byte-identical artefacts before and after on a fixture snapshot, apart from run ids and timestamps. Done: `pipeline/tests/test_golden_artefacts.py`.

### MOD-02: The forecast-frame contract

- **Absorbs**: 03 §12 P6.

#### Problem
The decision engine reads an implicit set of frame columns; nothing validates `expected_points.parquet`;
C1 borrows the champion's variance; captaincy by price and position travels as a forecast column.

#### Design
1. A versioned `forecast_frame` schema: per-gameweek mean and sd, minutes probabilities,
   `start_probability`, optional components, `strategy` id and digest.
2. The engine validates a frame before reading it; a frame without variance is rejected
   (Invariant 6).
3. `captain_score` moves from the forecast into the decision policy (DL-76).
4. `forecast.publishable(inputs, rules, config) → Forecast` is the factory's entry point; the stage
   only calls it.

#### Acceptance criteria
- [x] A frame missing an sd column, or with a negative sd, is refused before the engine runs. Done: `optimise/frame.py`; `pipeline/tests/test_forecast_frame.py` drives `recommend_transfers`, `optimise_squad` and `build_plan` with each, and `test_c1.py::test_a_broken_variance_is_refused_by_the_frame_contract` C1's own frame.
- [x] The captain rule reads price and position from the policy, not from the frame; the champion's captain is unchanged on a fixture snapshot. Done: B0's line reaches the rule as `captain_line.json`; `test_forecast_frame.py::test_the_champions_captain_and_vice_are_unchanged` pins the pre-change captains for xp_v1 and xp_v0.
- [x] `stages/forecast.py` holds no model choice. Done: it calls `champion().forecast`, and the allow-list no longer lets it import `forecast.live` or `forecast.xp_v0`.

### MOD-03: The strategy registry

- **Absorbs**: the model-id drift in 05 §2.2 and the `week.json` `model.id` mislabel.

#### Problem
Model ids, labels and roles are restated in at least six places, with `"engine"` meaning two
different models; the champion is a constant in a stage.

#### Design
1. `pipeline/src/fpl_dof/config/strategies/*.yaml`, one per strategy, validated by a schema: `id`, `label`, `role`,
   `published`, `forecaster` (`type`, model, config, training window), `policy`, `requires`
   ([05 §5.1](../05-target-architecture.md#51-a-strategy-is-a-forecaster-paired-with-a-decision-policy)).
2. `load_strategy(id) → Strategy` and `published_strategies()`; a digest per strategy over code
   version, config and training window.
3. Ids `c3` (champion) and `c1` (challenger) in R1.2.0; `engine`, `a` and `a_odds` join as
   challengers in R1.2.2. The web's old `champion` and `challenger` values in `?model=` and saved
   preferences map once to the new ids (DL-87).
4. A published `strategies` registry artefact (additive in contract v1) generated from the files,
   replacing `MODEL_REGISTRY`, `CHAMPION_MODEL`, `prospective/xp_accuracy.MODELS` and the schema
   enums.

#### Acceptance criteria
- [x] Exactly one champion, unique ids, every file valid — each enforced by a test. Done: `pipeline/tests/test_strategy_registry.py`; the champion must be published and a published strategy runnable by `Strategy.forecast` (`::test_an_unpublished_champion_is_refused`, `::test_a_published_strategy_must_be_one_strategy_forecast_can_run`).
- [x] No model id or label is defined outside the registry in Python or the schemas (a grep test). Done: `test_strategy_registry.py`; the frozen harness's exemption went with it (MOD-06).
- [x] An old `?model=champion` link and a saved `challenger` preference open the right strategy. Done in MOD-07: `strategies.json` publishes each strategy's aliases and the web maps them once (`web/src/components/models/models.test.tsx`, `web/src/data/registry.test.ts`).
- [x] Every published artefact names its strategy by registry id and digest. Done — artefacts a run publishes carry `strategy {id, digest}` (`test_strategy_registry.py::test_week_json_names_the_champion_by_registry_id_and_digest`, `test_models_compare.py`); the checked-in history files under `web/public/static/` describe the frozen models, are mapped by alias at load and are rebuilt from the registry in ORC-06.

### MOD-04: One decision path for every strategy

#### Problem
Three decision paths; only the champion gets a plan and chips; C1 advice is never ledgered; the
ledger's `models` key is never written.

#### Design
1. `decide(frame, squad_state, rules, policy) → Decision` in `core` produces week and plan for any
   strategy; `plan: false` skips the horizon solve.
2. The orchestrator runs every published strategy through it on the same snapshot and writes one
   `week` and `plan` per strategy (the `week_challenger` special case goes).
3. The ledger's advice file records every published strategy's advice under `models`, so no
   gameweek of the five goes unrecorded before R1.3.0's evaluation exists.

#### Acceptance criteria
- [x] Champion and C1 produce full weeks and plans through one function; their outputs differ only through their registry entries. Done: `decision.decide` (`decision/engine.py`), run per published strategy by `stages/week.py`; `test_decide.py::test_champion_and_c1_produce_full_weeks_and_plans_through_one_function`, `::test_every_published_strategy_gets_a_valid_week_and_plan`, and `::test_the_champions_week_is_unchanged_from_the_pre_change_path` (transfers, XI, captain pinned from the pre-change path). Both plan through `decide` at the policy level; production C1 runs `plan: false` until MOD-05 gives it means of its own beyond the next gameweek.
- [x] A failing strategy records "no advice" with its reason and stops no other strategy (NFR-15). Done: `test_decide.py::test_a_failing_challenger_records_no_advice_and_stops_nothing_else`; a champion week failure still fails the run (`::test_a_failing_champion_fails_the_run`), while its week and ledger entry are written before its plan or any challenger runs, so a champion plan failure of any kind is "no plan" and the week stands (`::test_a_champion_plan_that_raises_leaves_this_weeks_advice_written`).
- [x] `advice/gwNN.json` carries every published strategy. Done: under `models`, by registry id, each with its advice or its "no advice" reason; `test_decide.py::test_the_ledger_carries_every_published_strategy`.

### MOD-05: Five strategies ported

- **Absorbs**: F4 (M2 half-life into config), C1's hard-coded hyperparameters and missing seed.

#### Problem
A and A_odds exist only in the frozen bundle; C1 builds features outside the knowability seam,
borrows variance and fits without a seed.

#### Design
1. Register `engine`, `c3` (champion), `c1`, `a`, `a_odds` with stable ids; labels from the registry.
   Progress: `engine` is published (`week_engine.json`), with `forecaster.config` overrides, a typed
   `training_window` and enforced `requires` (`test_decide.py`, `test_strategy_registry.py`); `a` and
   `a_odds` are live (item 3).
2. C1 builds features through `FeatureSpec`, carries its own variance and takes its
   hyperparameters and seed from config (DP-06). Progress: done (`shadow/c1.py`, `forecast.c1`,
   `test_c1.py`): its own mixture variance, P(play) and B0; `FeatureSpec` features stamped `as_of`
   and checked by `assert_no_look_ahead`; seeded and deterministic; `all_seasons` keyed by
   `player_code`; one gameweek, `plan: false`; `Strategy.predictor` gives the walk-forward harness
   `fit_as_of`/`predict` for `xp_v1` and C1 (MOD-08 wires it into `walk_forward`).
3. A and A_odds are ported from `prospective/bundle/` into the factory; A_odds declares `requires`
   on the odds it reads, fail-closed without them. Progress: done (`shadow/a.py`, `forecast.a`,
   `test_a.py`; `shadow/a_odds.py`, `forecast.a_odds`, `test_a_odds.py`), each difference from the
   frozen original listed in its docstring and [05 §5.2](../05-target-architecture.md#52-the-registered-strategies).
4. First, the data change: `fplarchive` and `fdcouk` enabled in the live `run` job, since A and
   A_odds train on prior seasons and A_odds reads historical and upcoming odds; every `fdcouk`
   capture is kept (`retain`, DL-89 item 5, replacing DL-87's "immutable").

#### Acceptance criteria
- [x] Each of the five produces a valid frame and a full decision on a fixture snapshot. Done: `test_decide.py::test_every_published_strategy_gets_a_valid_week_and_plan` runs all five through `advise_all` (`forecast`, the frame contract, `decide`); `test_a.py` and `test_a_odds.py` validate their frames and decide them directly.
- [x] C1 passes `assert_no_look_ahead` and is deterministic across two fits. Done: `test_c1.py::test_a_history_row_kicked_off_after_the_deadline_raises`, `::test_two_fits_on_the_same_data_give_identical_frames`; the same pair in `test_a.py` and `test_a_odds.py`.
- [x] No hyperparameter or half-life is a literal in model code. Done: C1, A and A_odds read `forecast.c1`, `forecast.a` and `forecast.a_odds` (`test_c1.py::test_no_hyperparameter_window_or_half_life_is_a_literal_in_a_challenger`, an AST scan); M2's half-life is `forecast.team_strength.half_life_matches` (F4, `test_team_strength.py::test_the_half_life_is_read_from_config`).
- [x] The live run's bronze holds the archive seasons and each run's `fdcouk` capture, kept past the rolling window. Done: both enabled in `config/defaults/sources.yaml`; archive seasons are `immutable` and `fdcouk`'s `fixtures` resource `retain` (`test_retention.py::test_immutable_prior_season_bronze_outlives_the_window`, `::test_retained_captures_outlive_the_window_and_unretained_ones_do_not`, `test_external_sources.py::test_upcoming_odds_are_retained_yet_refetched_after_their_ttl`).

#### Acceptance criteria

### MOD-07: N-way comparison UI from the registry

- **Absorbs**: the model-list part of 03 §12 W2.

#### Design
1. The UI reads ids, labels, roles, colours and what each strategy publishes from the registry
   artefact; `MODEL_CHOICES`, `MODEL_FACTS`, `COLOURS` and `hasFullWeek` go.
2. The existing switcher lists every published strategy and applies on every page.
3. `/models` gains a multi-select comparison: this gameweek's advice as differences from the
   champion, xP on the players they disagree on, historical performance; every published strategy
   is selected by default (DL-87).

#### Acceptance criteria
- [x] A fixture registry with a strategy the TypeScript has never named renders in every model view. Test: `ComparePanel.test.tsx` ("a strategy the TypeScript has never named"), `models5.test.tsx`.
- [x] Any two to five strategies can be compared side by side; the champion is the default baseline. Test: `ComparePanel.test.tsx`, `strategyCompare.test.ts`.
- [x] Accessibility and offline checks pass (`verify:browser`). Run against a build served with a two-strategy registry (the champion's week and a second strategy's): `#/models` (with Compare) is in the route sweep, the focus-ring and offline checks, and the strategy switcher is driven; 225 checks, 0 failures.

### MOD-08: Standing multi-strategy backtest and experiments store

- **Absorbs**: 03 §12 P9; F5's model-card text.

#### Problem
The backtest grades one predictor against hard-wired baselines, records no digest, and its verdict
never reaches the CI model card.

#### Design
1. `walk_forward` takes a list of strategies and reports each against the champion in pairs;
   baselines are registered strategies of role `experiment`.
2. Every result is stamped with strategy digest and data window and appended to `ledger` under
   `experiments/`; the pipeline reads the latest verdict for the model card from there.
3. Tests move to the new interfaces (P9).

#### Acceptance criteria
- [x] The weekly backtest grades every registered strategy and writes one stamped record per run. Done: `factory/experiments.py` `grade` and `experiment_records`, appended by `backtest.yml`; `tests/test_experiments.py`; a local `fpl-dof backtest` on the 2024/25-2025/26 archive (2026-10-23) graded `c3`, `engine` and `c1` over 68 folds and wrote five records, `a` and `a_odds` as not graded until their ports land.
- [x] The published model card names the verdict for the champion's current digest, or says none exists for it. Done: `stages/forecast.py` reads `ledger/experiments/` (restored by `pipeline.yml`) through `factory.latest_verdict`; `tests/test_forecast.py::test_the_model_card_names_the_verdict_for_the_current_digest_or_says_there_is_none`, `tests/test_experiments.py::test_the_latest_verdict_is_for_the_current_digest_only`.

### MOD-09: First experiments — card rates (F1), training window (F3)

#### Design
Two declared experiment files: M7 reading each player's own card rate (F1), and the live training
window matching the backtest's (F3). Each names its hypothesis, falsifier, metric and length, runs
through MOD-08, and is promoted only past the E8 §5 bar with a DL entry.

#### Acceptance criteria
- [ ] Both experiments are declared, run, and their results recorded on `ledger`. Progress: both are declared (`config/experiments/`, `tests/test_experiments.py`) and ran locally on 2024/25-2025/26, results in each file; the record on `ledger` needs the CI backtest, which has not run with these strategies.
- [ ] Each ends in a recorded decision: promoted, rejected, or extended. Progress: F1 shipped as a bug fix ([DL-90](../../decisions/DL-90.md)); F3 is awaiting the owner (recommended: rejected).
