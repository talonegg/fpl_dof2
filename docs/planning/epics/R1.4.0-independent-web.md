## 1. Overview

The app and the data release on their own: data refreshes without rebuilding the app, the app
refuses data it cannot read, and adding an artefact or a UI variant is one change in one place.

**Where it starts** (survey of 2026-10-23):

- **Already done in R1.2.0.** The strategy registry is published (`strategies.json`) and the UI is
  built from it (MOD-07). One `DataStore` with a `useArtefact(key)` hook exists in
  `web/src/data/store.ts`.
- **Every pipeline run rebuilds and redeploys the whole site** (`deploy.yml`). The password hash is
  compiled into the bundle, so a kept build carries it.
- **The contract version is restated five times** (Python, the generated types, the smoke check,
  the service worker's cache name and URL pattern) and nothing in `web/src` reads it.
- **`fpl-dof publish` writes `web/src/contract/types.ts`** on every run; no CI step checks it.
- **Loading is still spread**: per-route hooks (`useFixtures`, `useLeague`, `useLog`, `useHealth`,
  `useLazyArtefact`), four spellings of "absent", a hand-kept offline warm-up list, and three
  checked-in static files under `web/public/static/` that bypass `Contract.write`. The data layer
  imports components (03 §12 W6), and the bench order differs between the languages (W2: Python
  ranks by P(plays) × xP, TypeScript by xP).
- **No UI flags and no experiments view.** Experiments are declared in
  `pipeline/src/fpl_dof/config/experiments/` and run only inside the weekly backtest.

```
┌──────────┬──────────────────────────────────────────────────────────┬─────────────┐
│ Item     │ Title                                                    │ Module      │
├──────────┼──────────────────────────────────────────────────────────┼─────────────┤
│ WEB-03   │ Types checked in CI; publish writes nothing to web/src   │ Contract    │
│ WEB-02   │ Contract versioning — built in R1.3.0 Drop A (DL-94)     │ Contract    │
│ WEB-01   │ App and data deploys decoupled                           │ Web/Orch.   │
│ WEB-04   │ Artefact registry and one loading hook                   │ Web         │
│ WEB-06   │ Experiments workflow and experiments in the app          │ Factory/Web │
│ WEB-05   │ UI flags                                                 │ Web         │
└──────────┴──────────────────────────────────────────────────────────┴─────────────┘
```

**Order.** WEB-03 first: the app's build must not depend on a pipeline run before it can be kept.
WEB-02 is built in R1.3.0's Drop A ([DL-94](../../decisions/DL-94.md)), so it is in place before
WEB-01 keeps an app beside newer data. WEB-05 last, and only with a first flag (Q5).

## 2. Stories

### WEB-03: Types checked in CI; publish writes nothing into `web/src`

- **Absorbs**: 03 §12 W4.

#### Design
1. `fpl-dof contract types` writes `web/src/contract/types.ts` from `contracts/`; `--check` fails
   when the file differs. The publish stage stops writing it.
2. The file stays checked in, and CI's Python lint job runs the check (Q1), so the web build needs
   no Python.
3. A `$defs` name collision fails generation instead of passing silently.

#### Acceptance criteria
- [ ] A schema change without regenerated types fails CI; a pipeline run leaves `web/src` untouched.
- [ ] Two schemas defining one `$defs` name with different shapes fail generation.

### WEB-02: Contract versioning

Built in R1.3.0's Drop A ([DL-94](../../decisions/DL-94.md)); specified here.

- **Absorbs**: 03 §12 W1, I-09.

#### Design
1. **One version constant** per side: Python's `CONTRACT_VERSION` and the generated TypeScript
   constant. The smoke check, the service worker's cache name and URL pattern and the data path
   derive from it.
2. **`contract_minor` in `meta`**, bumped by every additive change; the schemas' `const` stays the
   major.
3. **The app checks at runtime**: a different major refuses visibly, with what to do; data older
   than the minor the app needs shows a warning and renders what it can (Q2).
4. **A breaking change publishes `v2` beside `v1`** until the app has moved; the old shell's cache is
   purged when the major changes.

#### Acceptance criteria
- [ ] Data with another major shows the refusal screen; an older minor shows the warning.
- [ ] Changing the constant moves the data path, cache name and smoke check with no other edit.

### WEB-01: App and data deploys decoupled

#### Design
1. **The app is built once per change to `web/` or `contracts/`**, without `data/`, and kept as a
   workflow artefact named by commit and contract version (Q3). A missing or expired build is
   rebuilt, never skipped.
2. **A data deploy repacks**: the kept build plus the run's `data/v1`, uploaded to Pages, with no
   npm step.
3. **Deploy refuses data whose contract major differs** from the kept app's, and fails the run.
4. A change of `FPL_PASSWORD_HASH` triggers a rebuild, since the hash is in the bundle.

#### Acceptance criteria
- [ ] A data-only deploy takes no web build and serves the new data with the existing app.
- [ ] A major mismatch fails the deploy and leaves the live site as it was.
- [ ] The smoke test passes after a repack and after a rebuild.

### WEB-04: Artefact registry and one loading hook

- **Absorbs**: 03 §12 W3, W5, W6; the rest of W2.

#### Design
1. **The artefact registry is generated** from the contract's `ARTEFACTS` into TypeScript beside the
   types: key, path, required or optional, warm offline or not. The offline warm-up list and the
   smoke check read it.
2. **One hook**: `useArtefact(key)` with `loading`, `ready`, `absent`, `malformed` and `error`; the
   per-route hooks and the four "absent" spellings go.
3. **Every artefact goes through `Contract.write`**: the models history, the season replay (which
   gains a schema) and xP accuracy move from `web/public/static/` into the published data (with
   ORC-06), so a data deploy can change them.
4. **The data layer imports no component**: `effective.ts` and the replay type move into
   `web/src/data/`, and the effective squad is applied once.
5. **Bench order**: one rule, held in a lineup corpus read by both languages (Q4).

#### Acceptance criteria
- [ ] A new artefact needs one schema and one `ARTEFACTS` entry; the app, offline list and smoke
  check pick it up.
- [ ] An import-linter-style check fails if `web/src/data/` imports `web/src/components/`.
- [ ] Both languages pass the lineup corpus.

### WEB-06: Experiments workflow and experiments in the app

#### Design
1. **`experiment.yml`**, dispatched with the id of a declared experiment, runs the backtest for its
   baseline and variant only and appends the record to `ledger:experiments/` (Q6).
2. **An `experiments` artefact** published from the ledger: each experiment's hypothesis, falsifier,
   metrics, verdict and decision.
3. **A Models section lists them.** An experiment never changes the champion; promotion stays an
   owner decision with a DL entry past the E8 §5 bar.

#### Acceptance criteria
- [ ] Dispatching `f1_card_rates` writes a stamped record without a full weekly backtest.
- [ ] The app shows both declared experiments and their decisions, from published data only.

### WEB-05: UI flags

#### Design
`ui.json`, written by publish from a `ui` config block, lists each flag with its id, version and
default. Settings shows the flags with a per-device override in local storage, dropped when the
flag's version changes or the flag goes. Built with its first flag (Q5).

#### Acceptance criteria
- [ ] The first flag switches its variant from published data and from a device override.
- [ ] An override for a removed flag is ignored and cleared.

## 4. Questions for the owner

Each has a recommended answer; "yes" accepts it.

1. **Types in the build.** 05 §7.3 says the web build generates the types. Keep them checked in
   with a CI diff check instead, so the web build needs no Python? *Recommended: yes.*
2. **Older data.** When the data's minor is older than the app expects, warn and render rather than
   refuse? *Recommended: yes; refuse only on a major mismatch.*
3. **Where the kept app lives.** A workflow artefact, rebuilt when it expires? *Recommended: yes.* A
   release asset would tie the app to tags, but `main` deploys before it is tagged.
4. **Bench order.** Which rule is right, P(plays) × xP (Python's, the auto-substitution value) or
   xP (what the app shows today)? *Recommended: P(plays) × xP, in both.*
5. **UI flags.** What is the first UI variant you want to switch? A flag mechanism with no flag is a
   seam with nothing behind it. *Recommended: name one, or drop WEB-05 until there is one.*
6. **Experiment dispatch.** Declared experiments only, by id, rather than an ad-hoc config? *Recommended:
   yes; a hypothesis and falsifier are declared before the run.*
