## 1. Overview

The app is regrouped around the questions a gameweek asks, in eight sections, and the pipeline
publishes the four things the new sections need that it does not yet: each model's options this
week, underlying expected points, each model's season as if it had played, and the rivals' moves,
plus the odds.

| # | Section | Holds |
| --- | --- | --- |
| 1 | **Home** | Your squad with last gameweek's points and next gameweek's xP; each model's recommended team and changes; key alerts and insights; a data-health summary; last gameweek's insights |
| 2 | **League** | The mini-league table; each team's last gameweek on a click |
| 3 | **Models** | Each model's description; this season's comparison, refreshed after each gameweek (the ladder of its advice on your squad, the ladder as if it had played, and predicted xP against underlying xP and actual points); the 2025/26 playthrough, static per model update |
| 4 | **Last gameweek** | Each model's advice against what you did, and against what happened; the hindsight optimum against each model's view of it; all gameweeks (the season log) |
| 5 | **This gameweek** | Each model's decision and the options it weighed; **Plan ahead**: the multi-week plan and the chip calendar |
| 6 | **Scouting** | Fixture difficulty; players, with everything every source holds on them; odds when posted |
| 7 | **Analysis** | The squad builder; compare players |
| 8 | **Data health** | Sources, stages, gates, runs and refresh details |

Settings sits behind a gear in the header. The model selector and the run banner (gameweek,
freshness, trigger, the trust caveat) are in one global header. The password gate, offline use and
the contract's refusal and warning screens are unchanged. Old paths redirect, so no link breaks.

**Where it starts** (survey of 2026-10-24): twelve routes (`/`, `/scout`, `/player/:id`,
`/compare`, `/squad`, `/fixtures`, `/league`, `/log`, `/models`, `/settings`, `/health`, and
`/history`, which already redirects into `/models`); five per-route loading hooks beside
`useArtefact`; one checked-in artefact, `web/public/static/xp_accuracy.json`; `web/src/data/`
importing `components/squad/effective`; `fpl-dof publish` rewriting `web/src/contract/types.ts` on
every run with no CI check; the bench ordered by xP in TypeScript and by P(plays) × xP in Python;

### WEB-03: Types checked in CI; publish writes nothing into `web/src`

- **Absorbs**: 03 §12 W4.

#### Design
1. `fpl-dof contract types` writes `web/src/contract/types.ts` from `contracts/`; `--check` fails
   when the file differs. The publish stage stops writing it.
2. The file stays checked in and CI's Python lint job runs the check, so the web build needs no
   Python (§5 Q1).
3. A `$defs` name collision fails generation instead of passing silently.

#### Acceptance criteria
- [x] A schema change without regenerated types fails CI; a pipeline run leaves `web/src` untouched. Done: `ci.yml` lint job runs `fpl-dof contract types --check`; `test_publish.py::test_the_checked_in_types_match_the_contracts`; `test_cli.py::test_a_run_leaves_web_src_untouched` (a full run changes no file under `web/src`); the publish stage no longer writes types.

### ORC-12: Underlying expected points

#### Design
For each player and evaluated gameweek, the points the game's rules give to what he produced:
minutes and FPL's own expected goals, expected assists and expected goals conceded, read from
silver, scored under `rules` config (Invariant 2). The evaluation publishes predicted xP,
underlying xP and actual points, so a model's miss splits into forecast error (predicted against
underlying) and luck (underlying against actual). Each model's predicted xP is published per player, and the
hindsight diagnostics read it (D-37).

**As built** (`rules/underlying.py`, evaluation version 4). Per match: appearance by the minutes
played; xG times the goal points at his position; xA times the assist points; the clean sheet at
P(no goal) = `exp(-xGC)` under a Poisson on FPL's expected goals conceded while he was on, only at
or above the full-appearance minutes; goals conceded as the expected whole units,
`E[floor(N / goals_conceded_per_point)]`, `N ~ Poisson(xGC)`. Saves, penalties, cards, own goals,
Defensive Contribution and bonus have no expected input, so they are the actual (bonus keeps some
finishing luck; leaving it out would bias every underlying low). A match without an expected figure
scores that component's actual. A model's split is over its advised XI as the realised scorer
fielded it (auto-substitutions, armband), before hits, in `models.json`'s `actual`:
`underlying_points`, `forecast_error` = its xP less them, `luck` = its points before hits less them,
so xP less points is forecast error less luck. The per-player diagnostics carry `underlying_points`
in `log.json`. Contract minor 6.

#### Acceptance criteria
- [x] No scoring value outside `rules` config; a test pins one gameweek's underlying xP for a
  player against a hand calculation from the config. Done:
  `test_rules_realised.py::test_one_players_underlying_xp_is_the_hand_calculation_from_the_config`, with the
  goals-conceded units checked against a closed form; `rules/underlying.py` is inside the 100% rules
  coverage gate.
- [x] Models shows, per model, forecast error and luck for each gameweek. Done: `models5.test.tsx` "the
  models page splits each model's miss into forecast error and luck per gameweek (ORC-12)", from
  `test_evaluation.py::test_the_evaluation_scores_each_strategy_and_its_xp`.
